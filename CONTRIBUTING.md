# Contributing to BussoLabs projects

Thank you for helping improve our tools. A repository's own contribution guide and license take precedence over these defaults.

## Before you start

Search existing issues and pull requests. For a larger change, open a feature request before implementing it so we can agree on scope.

Report reproducible bugs with the affected version, expected behavior, actual behavior and the smallest set of steps that demonstrates the problem. Remove credentials and personal or customer data from logs and screenshots.

## Propose a change

1. Fork the public repository and create a branch for one focused change.
2. Follow the repository's setup instructions. Keep code, comments and tests in English.
3. Add a regression test when fixing behavior and run the documented checks.
4. Open a pull request explaining the problem, the change and how you verified it.
5. Address review comments before the maintainer integrates the change.

Forks and pull requests do not require organization membership. Do not request repository write access just to contribute.

Some products, including CloseYourIt, publish release snapshots from a separate development repository. Their contribution guide explains how accepted changes are imported and released with author credit. A project may require a contributor license agreement; read its agreement before submitting a contribution.

## Security and conduct

Use the private channel in [SECURITY.md](SECURITY.md) for vulnerabilities. Never publish exploit details, credentials or sensitive logs in an issue.

Participation follows our [Code of Conduct](CODE_OF_CONDUCT.md).
