# Security policy

## Report privately

Use [GitHub private vulnerability reporting](https://github.com/bussolabs/.github/security/advisories/new) to contact the BussoLabs maintainer. For a product with its own security policy, use the channel named there instead.

Include the affected repository and version, a description of the impact, and minimal reproduction steps. Use a local instance and synthetic data to demonstrate the issue. Do not access other users' data or test availability against shared or production systems.

Do not post vulnerabilities in public issues or pull requests. Never include live credentials, private keys, session cookies or customer data. If you already exposed a credential, revoke it through its owner; removing the text does not revoke it.

## Handling and supported versions

Reports are reviewed by the maintainer. We will discuss reproduction, remediation and coordinated disclosure privately. No response-time or bug-bounty commitment is implied.

Support windows belong to each product's security policy. This organization profile repository contains documentation, not a software release.
